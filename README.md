# Бот-прогнозы «Угадай старт Ильи»

## Запуск на GitHub Actions
Workflow `.github/workflows/bot.yml` запускает `python bot.py once 21000`: бот слушает Telegram
~5 ч 50 мин, потом следующий запуск (он уже стоит в очереди по cron каждые 5 часов) сразу подхватывает.
Пауза в ответах бывает только на стыке запусков, примерно раз в 6 часов (около минуты).
Пока бот работает, `scripts/save_db.sh` каждые 10 минут сохраняет зашифрованную копию базы
в ветку `data` (если база не менялась, сохранение пропускается), плюс финальное сохранение в конце.

1. Создай репозиторий на GitHub и залей код (все файлы, включая `.github/workflows/bot.yml`
   и `scripts/save_db.sh`). Репозиторий публичный: безлимитные минуты Actions, а база
   лежит зашифрованной. В приватном бесплатных минут (≈2000/мес) хватит меньше чем на сутки.
2. Settings → Secrets and variables → Actions → New repository secret (4 штуки):
   - `BOT_TOKEN` — токен от @BotFather
   - `CHANNEL` — `@username_канала`
   - `ADMIN_IDS` — id админов через запятую
   - `DB_KEY` — любая длинная случайная строка (ей шифруется база)
3. Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save.
4. Actions → predict-bot → Run workflow (первый запуск вручную). Дальше работает по расписанию.

**Не теряй `DB_KEY`**: без него базу не расшифровать.
Если cron остановится (GitHub отключает расписание в неактивных публичных репозиториях),
просто нажми Run workflow. В списке запусков будут «отменённые» (cancelled): это нормально,
так GitHub заменяет лишние ожидающие запуски.

Важно: правила GitHub для Actions на своих серверах ограничивают активность, не связанную
с разработкой, тестированием и публикацией проекта. Постоянно работающий бот находится
в серой зоне; возможные последствия: остановка запусков или отключение репозитория.
Для долгой работы надёжнее отдельный хостинг (раздел ниже).

## Постоянный запуск (мгновенные ответы)
Бот работает всегда, `python bot.py`. Два бота с одним токеном конфликтуют, поэтому
**перед переходом отключи workflow** (Actions → predict-bot → ⋯ → Disable workflow).

Главное требование: база `game.db` должна лежать на **постоянном диске**. Если хостинг
стирает файлы при перезапуске, пропадут все прогнозы. Путь задаётся переменной `DB_PATH`.

**Railway (платно, ~$5/мес Hobby):** New Project → Deploy from GitHub repo (подхватит `Dockerfile`).
Variables: `BOT_TOKEN`, `CHANNEL`, `ADMIN_IDS`. Settings → Volumes → добавь volume с путём `/data`.

**Любой VPS / домашний компьютер с Linux:**
```
git clone <репозиторий> && cd <папка>
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполни BOT_TOKEN, CHANNEL, ADMIN_IDS
```
Автозапуск: файл `/etc/systemd/system/predict-bot.service`
```
[Unit]
Description=predict bot
After=network-online.target

[Service]
WorkingDirectory=/home/USER/ПАПКА
ExecStart=/home/USER/ПАПКА/.venv/bin/python bot.py
Restart=always

[Install]
WantedBy=multi-user.target
```
затем `sudo systemctl enable --now predict-bot`. Базу `game.db` иногда копируй себе.

## Запуск локально
1. @BotFather → /newbot → токен.
2. Добавь бота в канал **администратором** (иначе он не сможет проверять подписку).
3. Скопируй `.env.example` в `.env`, заполни. Свой Telegram id узнаешь у @userinfobot.
4. `pip install -r requirements.txt` → `python bot.py`

## Как вести сезон (админ-команды)
- `/newstage Skate America | 2026-10-30 20:00` — создать старт и дедлайн приёма прогнозов (МСК)
- `/addside <id> Прыгнут ли параллельный квад с Диди?` — сайд-вопрос (ответ да/нет)
- `/stages` — список стартов
- после старта: `/result <id>` — внести фактические результаты (те же вопросы, что у игроков)
- `/score <id>` — подсчитать очки, бот сам выбьет отписавшихся

## Для участников
`/start`, `/predict`, `/my`, `/top`

## Очки за пункт
**Место и баллы:** 1 — верно · 0.75 — почти · 0.5 — примерно · 0.25 — мимо · 0 — пропущено.
Пороги — в `scoring.py` (`TOLERANCE`).

**Контент (КП и ПП):** оценивается каждый прыжковый элемент программы: 1 — стоит в прогнозе
на своём месте, 0.5 — есть в прогнозе, но не на своём месте, 0 — нет. Очки суммируются
(в КП максимум 3, в ПП максимум 6). Значения — `ELEMENT_EXACT` / `ELEMENT_PRESENT`,
лимиты элементов и каскадов — `LIMITS`, вес каждого пункта — `WEIGHTS` (всё в `scoring.py`).
Кириллица в названиях элементов автоматически превращается в латиницу.

Каскад, у которого угадан только первый прыжок (факт 4Lz+3T, прогноз 4Lz+2T), даёт половину
очков целого элемента: 0.5 на своём месте, 0.25 на другом (`CASCADE_PARTIAL`).

Максимум за один старт без сайд-вопросов: 13 очков (4 за место/баллы и 9 за контент).

**Ничьи в таблице:** при равной сумме очков выше тот, у кого больше точных попаданий
(пункты с полным баллом + элементы, стоящие ровно на своём месте). Это число видно в `/top`.

## Заметки
- Подписка проверяется при каждом /predict и раз в 6 часов; выбывший назад не возвращается.
- Данные хранятся в `game.db` (SQLite) рядом с ботом.
- Держать бота нужно на постоянно включённой машине (VPS, Railway, Render и т.п.).
